# VV Code 桌面端对话页集成研究计划

## 研究问题

在现有 Tauri + React 的 VV Code 工作台左侧新增“对话”页面时，应直接嵌入 `vvcode.top` 的网站对话页，还是采用开源对话 SDK/组件并调用现有 New API 推理接口？

## 子课题

1. 线上站点可嵌入性与登录复用
   - 确认 `vvcode.top` 的对话页路径、响应头、CSP、`X-Frame-Options`、Cookie 属性和 iframe 行为。
   - 判断当前桌面 OAuth 管理令牌能否直接让网站页面登录。

2. New API 对话页与认证机制
   - 核对 New API 上游项目的对话页实现、会话认证方式、可配置的嵌入限制及相关接口。
   - 识别服务端若要支持桌面嵌入需要增加的最小能力。

3. 开源对话组件/SDK 方案
   - 筛选适配 React、Tauri、OpenAI 兼容流式接口的成熟开源方案。
   - 比较许可证、集成重量、会话/Markdown/附件/工具调用支持与维护成本。

## 综合方式

结合当前代码中“OAuth access token 仅保存在 Rust 进程”和 Tauri CSP 约束，从短期交付、登录体验、安全边界、UI 一致性与长期可维护性五方面给出明确建议，并列出可验证的最小原型方案。
